# OpenMausBot plugin agent memory

- POM `cdylib` plugin scaffolded from `creating-pom-plugins`; the contract is in the POM repository's `docs/subsystems/plugins-ui.md` and `enterprise-licensing.md`. `src/abi.rs` is the panic-safe C ABI, `src/lib.rs` dispatches. Never block `query` (3 s IPC timeout).
- Upstream: `milind-soni/OpenMausBot` (Apache-2.0), consumed only as the published npm package `openmausbot`. Pins: `installer::NODE_VERSION`/`node_artifact` (nodejs.org archives and SHA-256s) and `runtime/package.json` + `runtime/package-lock.json` (embedded; `npm ci --ignore-scripts`, so npm checks every `integrity`). To bump: change the version in `runtime/package.json` and `installer::OMB_VERSION`, regenerate the lock with `npm install --package-lock-only`, run the tests (one asserts the lock has no install scripts and matches the version).
- `src/installer.rs`: download, extraction (regular files only, paths confined; npm and the CLI are run by path, so archive symlinks are skipped), `npm ci`, `.installed` stamp (`node <v>` + `openmausbot <v>`; a different stamp is an update). `register_pom` adds or refreshes `instances.pom` (`openai-compat`, `apiKeyEnv: POM_API_KEY`, loopback URL, first gateway model as default only when absent) in `<data>/config.json`, keeping every other field and never touching a `pom` instance of another driver. The key is passed only as `POM_API_KEY` in the server's environment (OpenMausBot's `operatorEnvKey`).
- `src/supervisor.rs`: install and server on a thread that lives as long as the server (PDEATHSIG follows the spawning thread). `node cli.js serve --no-pair --port <free> --data-dir <workspace>/.openmausbot` with a free `OMB_WEBHOOK_PORT`, `HOME=<data>/home`, a cleared environment. The server runs in its own process group; stop = SIGTERM to the group, SIGKILL after 5 s (Windows `taskkill /T`), because bots spawn engines, shells and browsers. Ready = `GET /api/health` answers 200 naming `openmausbot`. `lifecycle: on_demand`; `host.configure` relaunches an existing install.
- Phone access (`src/access.rs`, `src/account.rs`, screen `ui/src/screens/PhoneAccess.tsx`): `<plugin dir>/access.json` holds `{way: local|tunnel|tailscale, lan, port}`; default `local` keeps the free loopback port. Any other choice uses the fixed `port` (default 8799) and adds `--tunnel`/`--tailscale` and/or `--lan` to `serve`; OpenMausBot then requires pairing (Settings, Phone & devices) for each phone. `rpc.access`, `rpc.access.set` (saves and restarts), `rpc.account.login {email}` and `rpc.account.code {code}`: the tunnel needs `<data>/tunnel-account.json`, written by `openmausbot account login`, which this plugin runs with stdin piped and feeds the emailed code later, on its own thread. `--lan` advertises the first private interface address, so in Docker bridge networking the QR carries the container address and phones cannot reach it; Tailscale needs the `tailscale` command on the PATH where the node runs.
- `src/bridge.rs` (std only) is the `ui.upstream`: checks `x-pom-plugin-token`, refuses `sec-fetch-site` other than same-origin/none, strips cookie/authorization/origin/forwarding/`sec-fetch-*` headers and rewrites Host to loopback, so OpenMausBot sees its owner on loopback (it denies browsers loopback trust by `Sec-Fetch-*` and a WebSocket `Origin`; see upstream `server/request-auth.ts`). This is safe only because the node's proxy requires a POM session whose cookie is `SameSite=Strict`. The web app is built for `/`: the bridge rewrites root paths in HTML (`src=`/`href=`/`content=`), JS (`"/assets/`, `src:"/`, `href:"/`, `return"/"+`), CSS (`url(/`) and the web manifest, injects `SHIM` (prefixes fetch/XHR/EventSource/WebSocket/history/sendBeacon), replaces `frame-ancestors 'none'` with `'self'` and drops `X-Frame-Options`. Rewritten bodies are requested with `accept-encoding: identity`. Responses are `connection: close`; WebSockets are piped raw. A new upstream release can introduce new root-path forms: check the browser network tab for requests outside `/api/ui/plugins/openmausbot/proxy/` after a bump.
- Screen (`ui/src/screens/Main.tsx`) is Hermes's pattern: host version 7 loader, `waiting` calls `rpc.install`, `installing` maps `step`/`progress`, `ready` mounts the full-bleed iframe.
- Verify: `scripts/build-ui.sh`, `POM_UI_REQUIRE_DIST=1 cargo test --locked`, `cargo fmt --check`, `cargo clippy --locked --all-targets -- -D warnings`, `tests/test_ci_plan.sh`. Ignored tests: `installer::tests::installs_the_pinned_runtime` (network) and `bridge::manual::serve_in_front_of_a_running_server` (`OMB_PORT=<port>`, prints port and token, for manual browser checks behind a token-injecting front).
